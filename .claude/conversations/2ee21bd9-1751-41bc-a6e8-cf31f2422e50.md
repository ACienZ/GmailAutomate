## 根因找到了

**Gmail API 默认不返回 `Message-ID` 头部！**

看你的代码 `gmail_lib.py:63`：

```python
thread = service.users().threads().get(userId="me", id=thread_id).execute()
```

Gmail API 的 `threads.get()` 默认只返回有限的几个头部字段（`Subject`、`From`、`To`、`Date` 等），**`Message-ID` 和 `References` 不在默认返回列表中**。所以你在第 79 行的循环永远找不到 `Message-ID`，`message_id` 从未被赋值，最终在第 87 行触发 `UnboundLocalError`。

这并不是你的邮件有问题，而是 API 根本没把这个字段返回给你。

## 修复方向（仅分析）

需要在调用 `threads.get()` 时显式指定要返回的头部字段：

```python
thread = service.users().threads().get(
    userId="me",
    id=thread_id,
    format="metadata",
    metadataHeaders=["Subject", "From", "To", "Message-ID", "References"]
).execute()
```

你的代码中有两处 `threads().get()` 调用（第 35 行和第 63 行），都需要加上这个参数。

另外注意，代码中还有一个小 bug：第 87-88 行的 key 是 `"References "` 和 `"In-Reply-To "`（末尾多了空格），应该去掉空格。

## 真正的根因分析

搜索结果揭示了一个关键信息：**大约 1/10 的 Gmail 邮件会缺少 `Message-ID` 头部**，这是一个已知的 Gmail quirks。你的 3/70 ≈ 4.3%，比例吻合。

### 可能的原因（按可能性排序）

**1. 头部名称大小写不一致（最可能）**

Google Issue Tracker 上有一个已知 bug（#446748944）：通过 `users.messages.send` 发送的邮件，在发件人邮箱中存储的 header 名是 `Message-Id`（小写 `d`），而不是标准的 `Message-ID`（大写 `D`）。

你的代码第 78 行用的是**区分大小写**的字符串比较：

```python
if k["name"] == "Message-ID":   # 只匹配大写 D
    message_id = k["value"]
```

如果那 3 封邮件恰好来自通过 API 发送的邮件（比如你之前跑的程序发的），header 名就是 `Message-Id`，匹配不上。

**2. 某些邮件确实缺少 `Message-ID`**

`Message-ID` 在 RFC 5322 中是 "SHOULD" 级别（不是 "MUST"），所以某些自动化邮件系统、营销邮件、或者非标准邮件客户端可以不发这个头。Gmail 收到后会补充一个类似 `<-4185615914882731559@unknownmsgid>` 的占位 ID，但这个占位 ID 不一定会出现在 API 返回的 headers 列表中。

**3. 第一封邮件不是你想要的**

代码第 68 行：
```python
messages = thread["messages"][0]["payload"]["headers"]
```

如果线程的第一封邮件恰好是你程序之前发的（没有 `Message-ID`），而第二封才是对方回的（有 `Message-ID`），那也会找不到。
